# Service-owned native browser bootstrap

Fresh service setup allocates the native private browser capability only when the selected, digest-bound runtime manifest contains all four browser-bootstrap source records. Older service payloads remain usable without silently advertising that capability. Issuer delivery validates the capability against the native workspace owner and requires matching source records in the installed payload.

Browser-enabled service configurations use schema 2, matching the native reader and Direct browser configurations. Runtimes without the browser capability keep their existing schema 1 layout. A native regression saves and reloads the actual service configuration and verifies that a schema downgrade remains rejected.

The optional capability travels only in the private native authentication envelope. Both launcher and backend validate its exact shape, fixed native socket layout, key and safe generation. Backend configuration receives it without changing the existing host, port, LAN or Serve precedence. Network paths, arbitrary FDs and extra metadata are rejected. The original direct-start bootstrap remains unchanged.

Validation: seven portable policy/profile tests passed, including complete composition against pinned original source and the unchanged default producer. Production Release compilation and 26 focused native tests passed (23 issuer/boot, one selected-feature manifest test and two fresh-setup tests). Frozen source inputs remained unchanged and all captured compiler/test process groups were quiescent.

Eleven permanent launcher regression tests also pass, including private FD0 capability delivery with IPC3, rejection of malformed/configuration-bearing capabilities before child spawn, existing trial-update handling, helper loss and cleanup failure behavior. The browser cases load the exact registered launcher result and policy bytes. Three public-projection privacy checks pass as well.

The complete effective server graph now passes the pinned `effect-tsgo tsrs --noEmit` compiler. The proof HTTP layer captures configuration and environment services when constructing the layer, so request handlers no longer leak those dependencies into peer callers. Native bootstrap boundaries retain narrowly documented Effect diagnostic exceptions; authentication decoding uses a typed schema error, and pending browser-tab records preserve optional-field semantics. Ten appended patch records reproduce the checked source without changing the original pinned archive.

The composed route and FD0 decoder regressions pass together with source composition and source-integrity checks: 26 tests, zero failures or skips. They exercise valid private browser capabilities, malformed and oversized input, stale identity, extra configuration fields, missing secrets, Direct v1 preservation, service downgrade refusal and absent/incompatible descriptor protocols. These tests exercise the resulting source after all service patches, rather than an earlier intermediate fixture.

The producer now passes `--store-dir` explicitly to pnpm. Subsequent build scripts use the selected Node executable, preventing a script runner from silently reinstalling a different workspace dependency graph. Service packaging requires the full server typecheck before browser regressions, web/executable compilation and archive publication.
