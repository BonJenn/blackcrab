## Actual hidden, disabled or incomplete managed workflows

- **Automatic provider OAuth return capture:** `apps/web/src/components/settings/CodexSetupSection.tsx:456` only uses the native receiver when `desktopBridge.receiveProviderAuthCallback` exists. Without it, external sign-in opens but automated callback capture is absent; manual redirect paste remains. Native implementation/state rules are in `apps/desktop/src/ipc/methods/providerAuth.ts:16` and `apps/desktop/src/app/CodexAuthCallback.ts`.
- **Separate thread windows and pane tear-out:** `apps/web/src/lib/threadWindow.ts:13` requires the native method. Sidebar calls it at `components/Sidebar.tsx:2626`; pane drag-out at `components/panes/PaneHeaderControls.tsx:48`. A browser tab is not the same app window lifecycle.
- **OS notifications/attention:** `components/ThreadNotificationCoordinator.tsx:190` depends on the browser Notification constructor and permission, while native reveal/badge methods are absent. `components/settings/NotificationSettings.tsx:43` refuses notification modes if browser support/secure context is unavailable. In-app toasts and sound are separate existing paths; they do not prove native system alert delivery or click routing.
- **SSH environments:** `components/settings/AddEnvironmentDialog.tsx:645` only exposes its SSH choice with a bridge; native discovery at `:122` and `:277` is absent. `connection/platform.ts:378` explicitly rejects SSH provisioning as unsupported without it. Browser HTTP/relay access is not SSH provisioning or tunnel supervision.
- **Host exposure/tailnet/WSL controls:** `components/settings/ConnectionsSettings.tsx:410`, `:1230` and `:1594` gate desktop-owned settings. The managed supervisor's loopback host does not inherit those controls. WSL is a Windows-specific remaining target obligation.
- **Snap Shot:** `components/settings/SnapShotSettings.tsx:142` requires a native bridge/state before enabling capture. Global shortcuts, permission repair, staged shortcut config, pending capture recovery, ack and animation callbacks are missing. `lib/desktopSnapShot.ts:16` returns only the absent Electron bridge.
- **Native browser capture, annotation and recording:** `components/preview/previewBridge.ts:14` becomes null. `PreviewView.tsx:920` and `:930` hide capture/pick actions; `browser/browserRecording.ts:507` throws unavailable. Server-browser navigation still works but does not implement these native controls.
- **Local native browser and popout:** `browser/ElectronBrowserHost.tsx:134` exits for non-Electron. A desktop-runtime tab can show the message at `PreviewView.tsx:1032` rather than render. Server rendering has navigation/history/zoom/theme/cache alternatives at `PreviewView.tsx:241`, `:307`, `:344` and `:440`; it is not the native local guest/partition/capture system. DOM mini-player is separate from native PiP.
- **Browser-cookie import and OS permission repair:** `components/settings/IntegrationsSettings.tsx:1250` requires previewBridge to discover sources and `:1557` needs the native full-disk permission check. Existing server profile clearing is not importing this computer's browsers/keychain cookies.
- **Remote-editor launch:** `remoteOpen.ts:168` bypasses LocalApi and uses `window.location.assign` without desktopBridge. The managed navigation guard rejects custom editor schemes; the shipped HTTP(S)-only native opener does not close that workflow. Editor discovery at `:151` falls back to VS Code only.
- **Native menu/quit/paste/gesture behavior:** `shortcuts/dispatcher.ts:133`, `lib/desktopPasteAsText.ts:13`, `components/QuitHoldOverlay.tsx:25` and `HistorySwipeNavigation.tsx:109` depend on absent callbacks. DOM keyboard and paste handlers cover portions, but native menu delivery, quit protection, clipboard semantics and trackpad gesture boundaries remain unverified.
- **App-owned state across host origins:** `localApi.ts:60` uses browser persistence, and `connection/storage.ts:488` uses IndexedDB if no bridge. Host port changes alter origin, so these are not a stable app-owned preferences/encrypted catalog implementation. Current fragment+HTTP primary auth works through a separate path; it does not supply all Electron local backend controls.
- **Updater/CLI/activation/branding:** CLI row returns null at `components/settings/CliCommandSettingsRow.tsx:41`; updater calls return without bridge at `UpdateTrackSwitchDialog.tsx:98`; external link and CLI activation coordinators do not subscribe without their nested bridge objects. Fallback `branding.ts:23` is T3 Code and `:31` points downloads to t3.codes. Blackcrab must own these product/distribution routes while retaining attribution.

## Ordered coherent implementation increments

These are feature groups, not an instruction to make one PR per interface method. Split an increment only where it has an independently useful, reviewable acceptance boundary. Keep the existing strict per-origin/generation/window boundary and a capability-specific Blackcrab namespace.

1. **Stable app identity, settings/catalog and managed attachment lifecycle (N01; coordinate N08 identity policy).** Implement app-owned versioned settings and encrypted connection catalog, origin-to-native migration/quarantine, correct desktop platform/locale metadata and deliberate local backend enable/bootstrap behavior. Decide Blackcrab branding/telemetry/public-link ownership immediately. Do not expose static bootstrap secrets simply to mimic Electron getters. Tests: host restart on another port, blocked storage/secure-store unavailable, malformed/unknown keys, catalog migration, revoked/foreign origins, two windows and launch/disconnect persistence.
2. **Provider OAuth and OS/CLI activation (N04).** Implement receive/cancel as one correlated callback lifecycle, then safe OS web/app/CLI activation with readiness, queueing and completion acknowledgements. Use fork-owned protocol/redirect registration. Tests: state/nonce mismatch, fixed callback port conflict, cancel/timeout/retry, late callback after window or environment change, app cold start, duplicate/foreign activation and no accidental thread creation.
3. **Windows, native attention and menu/input lifecycle (N03).** Implement route-scoped secondary windows with independent grants, focus/reveal/fullscreen/zoom, native notification permission/display/click-to-thread and badge clear, native menu/quit/paste/gesture routing. OS notification delivery is an adjacent requirement beyond the listed methods. Tests: owner remains the host, unsent drafts survive close/reopen, correct host/thread on notification, denied permission, duplicate clicks, native menu focus, quit cancel, two windows and stale generations. If needed split attention/windows from menu/input as two coherent increments.
4. **File/context integration and safe editor/media actions (N02).** Finish the current icon increment, then address explicit selected local folder path, validated installed-editor launch, native paste/menu semantics and CORS-independent media retrieval. Keep working HTML file/theme import and DOM context menus. Tests: unsupported editor schemes, uninstalled editors, selected path scope, empty clipboard, malformed/cross-origin media URL and size limits, browser/Electron fallbacks, cancel and host switch. Theme import can retain its browser implementation until native behavior is separately needed.
5. **SSH gateway (N05).** Ship discovery/resolve, owned remote runtime/tunnel provisioning, scoped descriptor/token exchange and reconnect/password cancellation as one coherent system. Tests: unknown host keys, password/agent cancellation, retired prompt responses, wrong environment before bearer forwarding, dropped tunnel, interrupted waiter adoption, app restart, and cleanup of only owned resources. Never treat browser direct HTTP connections as completion here.
6. **Independent exposure/tailnet and Windows backend lifecycle (N06).** Connect UI to the Blackcrab supervisor and native configuration services. Respect maintenance/access scopes, explicit network consent and local/remote identity. Split Windows WSL as a platform increment. Tests: port and process ownership, switching exposure, auth required from another client, stale endpoints, failed tailnet setup/rollback, WSL path conversion and disabled-local behavior.
7. **Native browser guest/core and browser-profile import (N09).** Implement an actual supported local native guest with isolated partitions, local URL routing, navigation/history/zoom/audio/visibility/state/input and popup ownership. Reuse server host operations where they supply the same behavior, but verify the renderer difference. Add profile import with narrow OS permission repair and explicit per-profile read consent; no generic cookie/keychain read API. Tests: two tabs/profiles/environments, stale tab IDs, cross-origin guest IPC denied, popups, hide/show, native local dev server, profile isolation/import cancel and unsupported platform.
8. **Browser annotation/capture/recording/artifacts/popout (N10).** Add capability-gated workflows over that real guest, preserving permission, focus/activation, cancellation and provider send scopes. Use bounded issued artifact IDs instead of accepting arbitrary paths for reveal/copy. Tests: screenshot success/failure, recording start/stop/save/abort cleanup, hidden/minimized/locked host, annotations with denied send, file/media/clipboard limits, late callbacks and native PiP lifecycle. Server streaming and DOM mini-player do not certify these native paths.
9. **Snap Shot system (N07).** Implement permission setup, preview/apply shortcut transaction, global shortcut lifecycle, durable capture queue/read/ack and composer delivery with optional accessibility capture and feedback. Tests: denied/revoked OS permission, global conflict/no partial apply, restart with pending capture, duplicate ack, close/reopen during capture, focus and timeout cleanup. Preserve the pinned target's platform limitations explicitly.
10. **Owned release/update/CLI delivery (N08).** Finish independent trust keys/endpoints, exact-version/channel checks, download/install state, rollback, safe CLI path install/uninstall and OS open-app integration. Do not point Blackcrab updates, downloads or cloud sign-in at upstream-owned services. Tests: wrong signature/platform/version, interrupted download, channel mismatch, installed exact artifact, PATH shadow/conflict, uninstall unrelated file protection and signed packaged app behavior. Ownership decisions precede implementation; full distribution cannot be deferred out of parity.

## Shared verification boundary

Each increment needs exact-source adapter tests, capability-specific positive and negative native tests, stale origin/generation/window rejection, unsupported platform behavior, host restart/reconnect and packaged independent runtime evidence. Source reuse, a passing build or a browser fallback must never mark the neighboring native scenario complete. Map evidence to ledger X09/X10 and the relevant user scenarios; this inventory does not replace the full scenario ledger.
