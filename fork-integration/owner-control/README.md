## Proposed minimal private owner channel

A long-lived, separately scoped local supervisor must own the captured server child, settings transaction and exact artifact update lifecycle. Root attaches as a client; Root exit/disconnect must not stop an independently paired client's server. On Root restart, reconnect to this supervisor rather than spawn a conflicting owner or signal a runtime-record PID. A bounded explicit stop/restart affects all clients and must report the resulting disconnect/reconnect state.

Use an OS-local private socket (Unix domain socket on macOS), private owner directory0700/socket0600 and OS peer-UID verification. Socket location and expected environment come from trusted native state, never renderer input. Authentication of supervisor identity and artifact must be specified before use; mode bits alone do not distinguish another same-UID process. Reuse an inherited native-only capability/verified rendezvous mechanism; no LAN HTTP shutdown endpoint or new renderer-visible master secret. Root's renderer sees typed operation/results only. No environment/bootstrap secrets in URLs, error strings or renderer environment.

Prototype envelope: protocol1, environmentId, opaque supervisor epoch, expected settings revision, requestId, operation. Supported operations are status, setExposure, setTailscaleServe, restart, stop. It deliberately excludes arbitrary PID/path/exec and upgrades, which use existing capability-gated update contracts. All operations are fenced by environment and supervisor incarnation; serialized mutations compare revision immediately before effects. Restart's successful reply must be durably recorded before closing the old host so a lost reply cannot repeat effects. Maintain bounded authenticated request-id/result deduplication: prototype rejects known IDs but does not implement a durable cache. Re-read status/revision after conflicts. A new supervisor epoch invalidates stale commands. Settings revision advances only with committed mutation; lifecycle commands require a separate monotonic committed operation sequence/durable request journal if revision is unchanged. The current pure functions do not claim to implement those guarantees.

Preserve upstream payload/error schemas in the actual adapter; response union must carry the original typed exposure errors plus explicit owner unavailable/incarnation/revision conflicts. Native owner-port failures must not be converted into a successful public server operation. Unknown or mismatched owner identity fails closed. A dead supervisor must not be replaced while the server lock is held; no PID-record signals or lock deletion. For an existing host started without an attachable owner supervisor, either an authenticated in-process owner control extension or a clean explicit shutdown under the original captured owner is required before migration. Existing public RPC cannot perform that migration.

## Implemented captured-child core

`supervisor.mjs` implements serialized bounded requests, immutable input capture, environment/incarnation/revision fencing, bounded durable request IDs, captured-handle-only stop/restart, stale child-exit fencing and disconnect without stop. Every lifecycle mutation increments revision, including explicit restart/stop. The required `sessions.assertVerified` port must authenticate every request; this is not optional authentication supplied by a boolean RPC field. Trusted `children.start()` closes over the artifact/argv; messages cannot supply them.

`journal.mjs` supplies a bounded one-writer atomic rename+file/directory-fsync journal. Native startup must establish exclusive supervisor ownership and verify its private parent directory before constructing this port; it is not a cross-process lock or rendezvous implementation. Journal reads bind private-mode/UID/single-link validation and bounded bytes to one no-follow file descriptor. Concurrent writes are refused, input is captured before I/O, and a failed commit permanently disables that writer because publication may be uncertain. Own unpublished temporary files are cleaned without touching unrelated files. A pending request is durably reserved before any mutation. An uncertain write, interrupted request, lost ownership, or service error fails closed; pending recovery requires explicit reconciliation rather than replay. Successful effects get a durable completion entry before a reply. This conservative first core preserves original error identity and never retries a potentially applied setter, but does not yet classify definitely-no-effect upstream failures for continued availability. Journal capacity exhaustion refuses new mutations; no unsafe replay-ID eviction occurs.

Exposure is deliberately an injected original service (`setMode`, `setTailscaleServeEnabled`) returning its original `state`/`requiresRelaunch`, not a rewritten network/policy/settings implementation. Its requested relaunch executes through the captured supervisor child. Tailscale and update operations remain in their original service/launcher adapters; no raw Serve command or updater operation is added here. Status is the bounded supervisor snapshot, not a replacement for original advertised endpoint/status APIs.

Eight tests pass, including real subprocess restart/stop, an unrelated surviving subprocess, stale old-child exit, concurrent revision-conflicting setter/restart, client detach, original error identity, ownership loss and durable pending-write recovery rejection. Remaining wiring: verified private framing/peer authentication, exclusive supervisor launcher CLI/rendezvous, original Effect services and schemas, safe boot/migration policy, Rust owner IPC, update trial/rollback integration, durable reconciliation UX, and real remote endpoint/device acceptance. No production host was started, stopped or exposed by these tests.

Seven journal-specific tests additionally cover durable reopen, caller mutation, symlink/hardlink aliases, permissions, bounded size, corrupt authority/revisions, concurrent commits, failed publication cleanup and sequence exhaustion. The complete owner preparation suite currently has 16 passing tests. This remains preparation, with no production transport or remote exposure enabled.

An additional startup race test verifies that a stop received while the initial child launch is pending waits in the same serialized queue and stops the actual captured child. Initialization is now queued before it yields.


## Original exposure service adapter

`ExposureRuntime.ts` stages beside the pinned desktop sources and uses the original `DesktopServerExposure`, settings writer, network-interface reader, managed-policy decoder and Tailscale endpoint services. It creates an isolated Effect runtime with an explicit owned state home and no ambient T3 configuration. It preserves original typed setter errors and their persistence-before-state-change behavior. Starting/stopping the host, installing a tailnet route, service-manager installation, authentication and the native owner channel remain outside this adapter.

`prepare-exposure-probe.mjs` is developer acceptance tooling, not a production source importer. Supply a source tree from the authenticated pinned archive and a read-only pinned dependency cache. It checks the 25-file owner audit, compares every cached workspace bundle input with that source, enforces one physical Effect identity, and applies only candidate identity patch004 for independent administrator-policy paths. This candidate is not promoted to either active producer yet. The source references and emitted input hashes are consistency evidence; they are not publisher signatures.

The prepared adapter passed TypeScript6.0.3 and six real service/filesystem cases (seven Node test results including their parent): original defaults/local endpoints, saved Serve preferences across runtime recreation, interface-derived desired bind changes, captured-port reconfiguration, original typed persistence failure with unchanged effective state, and invalid private-state refusal. These tests open no listener and configure no tailnet route. Run `BLACKCRAB_TEST_OWNER_EXPOSURE_MODULE=/absolute/prepared/exposure-runtime.mjs node --test fork-integration/owner-control/exposure.integration.test.mjs` with Node26.12.1; absent the explicit module, that integration case skips. Production ownership/service-launcher wiring and real remote endpoint/device acceptance remain required.
