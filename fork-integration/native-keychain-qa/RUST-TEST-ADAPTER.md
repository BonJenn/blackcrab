# Proposed private test-only native seam — NOT implemented

Current production boundaries are src-tauri/src/managed_desktop.rs: verify_package at171; kind/namespace at193–197; package role at381–384; plist fields at395–398; descriptor at455/487; NativeDesktopOwner::open verifier call at683 and descriptor write743. Production APP_ID/PROFILE are constants20–21. ManagedNativeEntry uses the common owner. These checks must remain mandatory.

A later reviewed refactor can factor only the immutable identity expectation into a private typed `DesktopIdentityPolicy`:

- Production `verify_package` remains a noninjectable wrapper selecting the fixed production policy. No caller/env/CLI/manifest fields choose this policy. Preserve exact package name/main/upstream-commit checks; only the compile-pinned QA role differs. Its default artifact, inventory, source patch payload, link, digest, Mach-O, assets and plist verification behavior stays identical.
- A `#[cfg(test)]` exact QA policy lives in a NEW test module, e.g. src-tauri/src/managed_native_keychain_qa.rs, registered only from the existing test acceptance module. It pins ONE reviewed nonce/appId/appName/new kind/namespace and exact package role `native-keychain-qa`, all identity source records, source graph and actual complete artifact digest/archives after the real QA build. A path may be a locator; expected digest/name/kind cannot come from env or external JSON. Unknown nonce, altered identity, wrong graph/digest, old mock QA, ordinary production or arbitrary QA artifacts fail.
- Both wrappers call the same actual verifier internals; no alternate extractor, fake verifier, blind allowQA bool or verifier bypass. Production binaries do not compile the QA policy/entrypoint. The QA package's namespace vector is exact: unique appId/name, unchanged blackcrab renderer scheme and blackcrab-managed-v1 logical profile.
- Carry the verified immutable identity into the shared descriptor builder and launch pipeline. Production passes the production constant; test-only QA passes only the compile-pinned verified QA policy. Reuse actual captured-child launch, private FD3 descriptor, FD4 standard paired credential broker, host authentication/proof, scope binding, private fresh root, navigation guards and cleanup. Do not forge an owner, widen scopes or create a second client/service implementation. The descriptor differs only in its fixed QA appId, matching the QA codec constant; profile naming/auth wire is unchanged.
- Keep production ManagedNativeEntry/issuer selection unchanged and unable to invoke QA. No Tauri command, renderer control, production env switch, CLI escape hatch, fallback to QA verification or postfailure adoption. QA runs only in an explicitly filtered test fixture with compile-time pins and captured actual process authority.

Required future Rust regressions before any launch: unchanged production artifact accepted under production policy; exact QA artifact accepted only under its compiled test policy; each kind/appId/name/profile/scheme/digest/source record mismatch rejected; QA rejected by ordinary production path even in test builds; descriptor appId matches the verified QA identity while FD/auth/scopes are identical; failed verifier never spawns. An actual native launch/keychain persistence test requires separate approval and fresh owned roots. None of that is compiled or executed by this subtree's current Node tests.
