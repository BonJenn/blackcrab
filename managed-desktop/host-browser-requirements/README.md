# Staged native browser host requirements

These ten exact records are NOT enabled by the default managed-host registry. They apply only after the pinned proof9 base in base.json; apply.mjs delegates to the generic atomic-preflight source patcher. No current default host API or payload changes merely by adding this directory.

The owner sends desktopBrowserSocket:{path,key,generation} through private bootstrap FD3 only. Path is a canonical short absolute Unix socket path (at most100 UTF8 bytes), with an owned0700 parent; key is independent lowercase64hex, generation a positive safe integer. The host obtains environmentId from its real ServerEnvironment, not caller input. The native client receives browser:{kind:"leased-uds-v2",path,key,generation,environmentId} through its own private FD3; generation must equal descriptor.owner.generation. No public discovery, CLI flag, environment variable or server-settings field is introduced. The owner persists this capability only while the same captured host survives, and rotates all three fields for a newly spawned host.

The socket layer resolves after listen and chmod0600 succeed, never after a peer connects. HTTP readiness alone does not establish socket readiness. Root must verify the compiled ten-record artifact and its cryptographic host identity, then bound its wait for the owned0600 socket before emitting the native descriptor. Listener configuration failure fails the layer; there is no silent fallback. Existing paths are refused, never unlinked. Windows fails closed. With no socket configured, the original FD6/7 implementation remains; mixed socket and either FD is refused.

Version2 binds environment/generation and independent fresh server/client nonces using mutual HMAC. Every command/event has a directional HMAC and strictly increasing sequence; replay, modification, unknown controls and oversized frames terminate the connection. Both directions have a64MiB frame ceiling, including screenshots; overflow fails rather than truncates. Only one authenticated peer and sixteen total pending/live sockets are allowed. No offline command replay exists. Disconnect fences peer/tab/endpoint owners, pending publication/cleanup and downloads. Reattachment announces actual tabs and resnapshots current agent activity. Original10second awaitAttached/headless policy and physical screenshot serialization remain.

Public-surfaces.json captures the exact pinned public projection expressions and source hashes; host-browser-public.test.mjs executes them against private sentinel state. The public environment/config, process diagnostics and telemetry projections do not spread internal ServerConfig. Settings schemas are independent user-settings data. Capability values never enter argv; normal transport filesystem errors are sanitized. This is bounded source/dataflow evidence, not a claim that heap snapshots cannot contain process memory.

No fresh heavy host/client build or native CDP/reconnect acceptance has run for these production records. The earlier prototype missed its pinned10second attachment window. Root adoption and actual native lifecycle/agent-browser validation remain gates; no provider turns were performed.
